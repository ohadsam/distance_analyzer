# Momentum — visual foundation v1.0
Internal working name; no final wordmark approved. Hebrew-first RTL, English equal.

## Geometry and brand
Use a 24×24 viewBox for UI, 2–22 optical bounds, 1.8 unit strokes, round joins/caps, no gradients or shadows. Use currentColor for UI. Brand mark is a continuous rising path with a start node and forward arrow; do not mirror the brand. App icon uses a 64×64 rounded tile; platform masks are applied by the OS. Maintain 8 units clear space around the mark. No wordmark until name is confirmed. Art uses 64×64, illustrations 160×140, widget shells 160×80, backgrounds 320×220. Scale uniformly; never stretch. Avoid adding decorative detail to UI glyphs.

## Layout and type
4 dp base spacing; 8/12/16/24/32 dp spacing; 12 dp cards, 8 dp controls, 16 dp hero panels. Minimum touch target 48×48 dp. Use Noto Sans Hebrew and Noto Sans or system equivalents; body 16 sp/24, secondary 14/20, title 24/32, metric 32/40, captions 12/16. Support font scaling and wrapping; do not truncate essential metrics. Use tabular numerals for measurements. Hebrew labels align start (right), English start (left). Use logical start/end margins and bidi isolation for mixed numbers and units. Localize units and date formats; never embed text in artwork. Mirror only navigation back/forward; keep maps, compass, clocks, charts, play and brand orientation stable. Use actual data labels and screen reader descriptions.

## Colour
Eight packs, each light and dark, defined in tokens.json. Semantic tokens only: background, surface, text, muted, primary, onPrimary, outline, success, warning, danger, walk, run, focus. Walk and run retain distinct stable colours and icons. Do not rely on colour alone. Use onPrimary only over primary; text/muted and status colours over surface; focus over background. Contrast audit uses WCAG relative luminance and unrounded ratios; 4.5:1 for normal text and 3:1 for tested non-text boundaries. No claim of whole-app compliance: test actual rendered screens, disabled states, overlays and charts separately. Art uses default Momentum colours in this version; replace explicit art fills/strokes with matching pack primary and light accent at integration, and verify contrast for informative marks. Backgrounds are decorative only; place text on a separate opaque surface, not on the artwork.

## Components and motion
Use start-aligned labels, clear metric units, a visible pause/stop action, and text alternatives to progress bars. Widget SVGs are decorative shells, not live widgets; app renders localized values and actual progress. Badge symbols identify achievements but do not define thresholds; product logic owns eligibility. No pressure to exercise or competitive body comparisons. Animation specifications are in motion.json; implement with native transforms/opacity, honor reduced motion, never animate essential text or use flashing. Route animation requires normalized pathLength=1 at integration. No background looping by default.

## Integration and limitations
assets.json contains standalone SVG strings and metadata; svg/ contains the same assets separately. Use ui-* with currentColor. All SVGs are XML-parsed by build.py; contrast pairs are programmatically checked. Preview is self-contained HTML. The four backgrounds share one motif; widget shells share geometry; art and badge variants reuse the icon geometry intentionally. This is a foundation prototype, not a final bespoke illustration collection or native widget implementation. No actual runtime animations, platform export sizes, final wordmark, device rendering or optical QA are included. App icon tile is a master, not a complete Android adaptive icon or iOS asset catalog. No trademark clearance performed. Future work should add distinct scenic art and validate on-device at 16/24/32 dp and in both directions.
