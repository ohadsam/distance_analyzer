# Testing

Run all: `npm run check && npm test && npm run e2e` (CI runs the same plus Android unit tests, lint and the release build).

| Layer | Command | What it proves |
|---|---|---|
| Static | `npm run check` (`scripts/static-checks.mjs`) | every JS file parses; no `innerHTML`/`eval`/`document.write`/`replaceChildren(args)`; no external URL (CSP is `'self'`); no inline `style=`; every JS/CSS/icon is in `sw.js` SHELL and exists |
| Unit | `npm test` (`node --test tests/unit/*.test.js`) | pure logic, below |
| E2E + UI | `npm run e2e [-- --shots dir]` (`tests/e2e/smoke.mjs`) | real Chromium against `web/`: flows, axe-core at zero violations, 320 px overflow, screenshots on request. `ONLY="text" npm run e2e` runs matching steps |
| Android | CI only | `gradle testDebugUnitTest`, `lintDebug`, `assembleRelease` (no Android SDK in the sandbox) |

## Unit tests (tests/unit)
- `share-whatsnew.test.js`: WhatsApp / e-mail links carry the whole encoded text (and are capped); `changelog.js` has the running version first, equal bullet counts in en and he, and every version also in `docs/CHANGELOG.md`.
- `workout.test.js`: haversine, distance/moving time/pace/splits from a 3 m/s run, rejected fixes, pause gaps, finish, sanitising hostile records, regressions (pace after pause, finishing while paused).
- `cadence.test.js`: step detector on synthetic accelerometer signals (`_signal.js`), silent learning then lock, irregular rhythm never locks, stop/pause, re-lock, manual rhythm, breathing pattern, untrusted pattern key.
- `engines.test.js`: stats (weeks start Sunday, buckets, streak, bests, weather buckets, filters), steps (stride, quality, series, recommendation), effort (minutes, bar from median, ceiling, alerts long/fast/surge, gentle new target), reminders (sanitise, due window incl. midnight, smart nudge rules), alerts (sanitise, bounds), search (Hebrew/English normalisation, ranking).
- `design.test.js`: WCAG contrast of every pack/mode from `design/stepup/tokens.json`; generated files are up to date (`npm run design`); icon data uses only safe elements.
- `plan.test.js`: plan structure, growth and recovery weeks, ceilings by age, interval progression, goal ramps, habit days, matching (kinds, length, one workout once), catch-up (free days, hard sessions apart, skip), adaptation, progress, hostile storage, reminder entries.
- `routes.test.js`: simplify/sample/distance, route matching on synthetic noisy tracks (same route, off by metres, other street, reverse, partial, different length), ghost distance, sanitisers, weather at a workout hour, route progress/trend, best context, suggestions by time of day and recency, one-time skipped.
- `reco.test.js`: forecast URL privacy + hostile answer normalisation, comfort factors, routine detection, best/avoid windows on a hot day, habit windows follow the routine, rain moves the window, tomorrow, effort/steps/streak recommendations.
- `core.test.js`: `cleanText`/`clamp`, he/en string parity (keys and placeholders), language resolution. `version.test.js`: version.json = package.json = sw.js, CHANGELOG entry, user guide exists. `docs.test.js`: every source file is listed in `docs/CONTEXT.md`.

- `routes.test.js` also covers the Mercator view and tile list; `indicators.test.js` also covers records. `update.test.js` also covers backup parsing and preferences; `engines.test.js` covers month series and week bars. `indicators.test.js` (live indications: records, last time, per-km, once each, no "0 m"). `update.test.js`: version compare, hostile release JSON, update-check outcomes, share fallbacks, weather banner choice and that every art file exists, spoken cues (queue, language, no throw). `cadence.test.js` also checks the flash-safe visual divisor.

`routeplan.test.js`: via-point sets, service parsers (junk rejected), elevation hysteresis, way kinds and route classification, crossing counting, scoring with preferences and missing data, ranking / de-duplication, the orchestration against a fake network (also with elevation / street data failing and nothing routable), map helpers.

New steps (0.24.0): `permissions` (Settings rows with state and asking; the start-up sheet on the Android stand-in - allow all, blocked shows "open settings", "later", "do not ask again" - and in a browser, Escape, never over a workout, axe), `defaults` (map, weather and planner on at first launch; the position is saved without a tap; turned off = nothing stored), `in-app update on Android` (the one-time OK, nothing downloads before it, progress / confirm / done / errors, manual link, a refused start). Kotlin: `PermMathTest`, `UpdateMathTest` (CI only).
New step (0.19.0): `round-8 art` (characters animate, calm switch, active navigation icon, gauge needle). New steps (0.18.0): `map screen` (measuring, undo, save, street-map opt-in loads tiles only after the tap), `route planner` (no request before consent, ranked cards with crossings / surface / climb, save, follow, the A-to-B form, Hebrew failure messages, revoke) using `tests/e2e/mocks.mjs`, `global search: actions, data facts and guide topics` (+ the guide walk-through), `live map explains itself`. A new install shows no widgets until the first workout: tests that need them seed a workout first.

`fakeAndroid(init)` (option `native: {}`) stands in for `window.StepUpNative`: counts service start/stop, serves fixes/steps, records the notification schedule, serves a pending href; its fix buffer survives a reload through sessionStorage like the native file. Helpers: `newPage({lang, clock, clockAt, signalGapMs, geo})`, `seed(page, rows)` saves workouts through the app's own store, `fakeFootsteps` injects `devicemotion` events (desktop Chromium has no `DeviceMotionEvent` constructor: use a plain `Event`).

## Gotchas learned
Install the Playwright fake clock BEFORE page init scripts that use timers; `page.clock.install()` keeps time flowing; the page CSP forbids `addScriptTag` (use `page.evaluate`); wait for the settled DOM after async redraws (dashboard redraws are async, newest draw wins); Chromium exposes `DeviceMotionEvent.requestPermission` but the app must not gate listening on it.
